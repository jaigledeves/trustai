# TrustAI Project Constitution

## Engineering Constitution & AI Agent Playbook

**Versión:** 1.1
**Estado:** Approved
**Fecha:** Julio 2026

# Purpose

Este documento define la identidad, principios, reglas de ingeniería y
forma de trabajo del proyecto TrustAI. Su objetivo es garantizar que
cualquier ingeniero o agente de IA pueda continuar el proyecto
manteniendo coherencia técnica y estratégica.

# Product North Star

Construir la plataforma de referencia para la confianza digital sobre
activos digitales mediante Inteligencia Artificial y Blockchain.

# Golden Rules

1.  Diseñar antes de implementar.
2.  Documentar antes de programar.
3.  Toda decisión relevante requiere justificación (ADR).
4.  Blockchain solo para confianza e inmutabilidad.
5.  IA debe generar valor medible.
6.  Mantener el MVP pequeño y demostrable.
7.  Pensar siempre en producto, no solo en el TFM.

# Success Criteria

-   TFM sobresaliente.
-   Repositorio profesional.
-   MVP desplegable.
-   Arquitectura escalable.
-   Base para un SaaS.

# Definition of Done

Una funcionalidad está terminada cuando: - Tiene requisitos
documentados. - Tiene diseño aprobado. - Tiene pruebas. - Está
integrada. - Está documentada. - Actualiza la memoria técnica si
procede.

# Documentation Standards

Cada documento incluirá: - Objetivo - Alcance - Contexto - Decisiones -
Alternativas - Riesgos - Referencias - Checklist

# Architecture Governance

Mantener arquitectura modular, API First, separación de
responsabilidades y seguridad por diseño.

# ADR Policy

Toda decisión sobre tecnologías, arquitectura, datos, IA o blockchain
generará un ADR numerado.

# Git Strategy

-   main
-   develop
-   feature/\*
-   hotfix/\* Commits pequeños, descriptivos y trazables.

# AI Usage Policy

La IA asistirá en: - documentación - diseño - generación de código -
revisión - pruebas Nunca sustituirá el criterio de ingeniería.

# MVP Scope Control

Solo se incorpora una funcionalidad al MVP si: - resuelve un problema
central, - puede demostrarse, - no compromete el calendario del TFM.

# Quality Attributes

Seguridad, mantenibilidad, observabilidad, escalabilidad, rendimiento y
experiencia de usuario.

# Risks Register

-   Complejidad técnica.
-   Costes de IA.
-   Integración blockchain.
-   Protección de datos. Cada riesgo tendrá seguimiento y mitigación.

# Repository Vision

docs/ backend/ frontend/ smart-contracts/ infrastructure/ tests/ .github/

# Communication Principles

Explicar siempre el porqué de las decisiones. Registrar cambios
importantes. Evitar deuda técnica innecesaria.

# Roadmap Philosophy

El roadmap evolucionará mediante versiones incrementales y entregables
funcionales.

# Final Commitment

Este proyecto debe poder sobrevivir al cambio de desarrolladores,
tecnologías o asistentes de IA gracias a una documentación completa y
una arquitectura bien fundamentada.
