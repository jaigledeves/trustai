Motivación

El problema

Sin solución

  • Un PDF revisado por IA es indistinguible de uno falsificado
  • No existe mecanismo para verificar independientemente la integridad de una evaluación
  • Toda verificación requiere confiar en la plataforma emisora

Con TrustAI

  • Hash canónico del registro anclado on-chain (inmutable)
  • Verificación pública sin confiar en TrustAI
  • Cualquiera puede recalcular el hash y compararlo
¿Por qué blockchain? El estado de la cadena es auditable públicamente y no depende de TrustAI para existir — ni siquiera para sobrevivir.

Paquete central

@trustai/dtr-core

Paquete puro TypeScript — sin framework, sin base de datos, sin IA. La única fuente de verdad sobre el protocolo DTR.

canonicalize(dtr)

Serialización determinista: claves ordenadas, números normalizados, campos nulos excluidos. El mismo DTR produce la misma cadena en cualquier entorno.

hashDtr(dtr)

SHA-256 sobre la representación canónica → string hex de 64 caracteres. Idempotente: mismo DTR → mismo hash, siempre.

verifyDtr(dtr, onChainHash)

Recalcula el hash y compara contra el ancla. Devuelve VALID | INVALID | NOT_FOUND.

Blockchain

AnchorRegistry

Contrato mínimo, sin sorpresas, sin owner.

anchor(bytes32 hash)

Registra el hash en el estado de la cadena. Emite Anchored. Idempotente — no revierte si ya existe.

exists(bytes32) → bool

Consulta pública, gratuita, sin permisos. Cualquiera puede verificar.

  • Sin ownership ni control de acceso
  • Chain id: 84532 (Base Sepolia)
  • Probado con Foundry (unit + fuzz)
  • Desplegado: 0xe6738f...607C22
ADR-003: ERC-721 descartado — overhead innecesario para MVP. El contrato mínimo tiene la menor superficie de ataque posible. 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract AnchorRegistry {
    event Anchored(bytes32 indexed hash);

    mapping(bytes32 => bool) private _anchors;

    function anchor(bytes32 hash) external {
        if (!_anchors[hash]) {
            _anchors[hash] = true;
            emit Anchored(hash);
        }
    }

    function exists(bytes32 hash)
        external
        view
        returns (bool)
    {
        return _anchors[hash];
    }
}

Adaptador de IA dual

Puerto IAiReviewer — el dominio no sabe qué modelo usa ni si hay red disponible.

Datos sintéticos deterministas. Sin red, sin coste, sin latencia. Activo en CI y entornos de desarrollo.

OpenAiAdapter

Envía el texto del activo a GPT-4o. Respuesta validada con Zod antes de persistirse en el DTR.

Selección por variable de entorno: AI_ADAPTER=stub|openai

Cierre

Conclusiones

IA + blockchain resuelven el problema de la confianza sin requerir que el verificador confíe en el emisor.

La arquitectura hexagonal permitió desarrollar y testear el dominio completamente aislado de la infraestructura — sin acoplamiento a ningún framework ni servicio externo.

dtr-core como paquete puro garantiza que la canonicalización y verificación son reproducibles por cualquier implementación futura, en cualquier lenguaje.

El MVP está en producción, con flujo completo probado end-to-end contra Base Sepolia real y 327 pruebas automáticas pasando en CI.
